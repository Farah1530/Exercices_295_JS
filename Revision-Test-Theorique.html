Objectif

Créer un projet avec Node.js et Express

Langage compilé ou interprété

C'est une diapositive entière du prof, et c'est ce qui explique ce qu'est Node. JavaScript est un langage interprété, et Node est son interpréteur.

CritèreCompiléInterprété
Traduction Le code source est traduit en une fois en langage machine Traduit ligne par ligne au moment de l'exécution
Fichier généré Un binaire exécutable (.exe, .dll) Aucun. Le code source est relu à chaque exécution
Vitesse Rapide, le code est déjà optimisé Plus lente, à cause de l'interprétation à la volée
Préparation Doit être compilé avant d'être exécuté Peut être exécuté directement
Exemples C, C++, Rust, Go, Swift Python, JavaScript, PHP, Ruby, Bash
Outil requis Un compilateur (gcc, rustc) Un interpréteur (python, node)
Node.js
L'interpréteur qui permet d'exécuter du JavaScript en dehors du navigateur, directement sur une machine. C'est ce qui rend possible d'écrire un serveur en JavaScript.
npm
Le gestionnaire de paquets de Node. Il télécharge les bibliothèques écrites par d'autres et gère leurs versions.
Express
Le framework standard qui offre un ensemble de fonctionnalités pour construire des applications web et mobiles. Il simplifie la gestion des routes, la lecture des requêtes et l'envoi des réponses.
nodemon
Un utilitaire qui redémarre automatiquement le serveur dès qu'un changement est détecté dans les fichiers sources.

Les commandes, avec les options du prof

# cree le package.json (-y = reponses par defaut)
npm init -y

# --save : dependance necessaire en PRODUCTION
npm install express --save

# --save-dev : dependance de DEVELOPPEMENT uniquement
npm install nodemon --save-dev

# demarre le serveur (script "start")
npm start

La différence entre --save et --save-dev est une question classique. Express est indispensable pour faire tourner l'application chez le client final. Nodemon ne sert qu'à toi, pendant que tu développes.

Les trois fichiers et dossiers créés

package.json
La carte d'identité du projet : son nom, ses dépendances, ses scripts. Le seul des trois qu'on met sur GitHub.
package-lock.json
Note les versions exactes installées, pour que le projet s'installe à l'identique sur une autre machine.
node_modules/
Le code des bibliothèques téléchargées. Jamais versionné : npm install le recrée à partir du package.json.

Le serveur minimal

// import marche grace a "type": "module"
// sinon : const express = require('express')
import express from 'express';

const app = express();
const port = 3000;

// middleware : lit le JSON du body
app.use(express.json());

app.get('/', (req, res) => {
    res.send('Hello World!');
});

app.listen(port, () => {
    console.log(`Example app listening on port ${port}`);
});
À savoir dire : le serveur « écoute » sur un port. localhost désigne ta propre machine, et 3000 est la porte sur laquelle Express attend les requêtes. D'où l'adresse http://localhost:3000.
2
Objectif

Créer une API REST avec des données simulées dans un fichier JavaScript

Définition d'une route, mot pour mot : une règle qui dit que si une requête HTTP arrive avec l'URL précisée et la méthode précisée, alors elle exécute le code donné.

Une route se définit par trois choses

1. Sa méthode HTTP
GET, POST, PUT, DELETE…
2. Son path
L'URL de la route, par exemple /api/activities/:id
3. Sa fonction
Le code exécuté quand la route est appelée. Elle a deux paramètres : la requête (URL, paramètres, body) et la réponse renvoyée au client.

Anatomie d'une route

activitiesRouter.get('/:id', (req, res) => {
    // req.params : parametres d'URL, du TEXTE
    const id = parseInt(req.params.id);

    // req.body : donnees du client (POST, PUT)
    // const { name, startDate } = req.body;

    const activity = activities.find(a => a.id === id);

    // res.json() repond et termine
    res.json({ activity });
});

Les quatre verbes, selon le prof

VerbeRôleURLBody
POSTCréer une nouvelle ressource/api/activitiesOui
GETLire une ressource précise ou une collection/api/activities
/api/activities/2		Non
PUTMettre à jour une ressource/api/activities/2Oui
DELETESupprimer une ressource par son identifiant/api/activities/2Non

Les recommandations de nommage REST

Une diapositive entière y est consacrée, c'est donc matière à question.

Des noms, pas des verbes
L'action est portée par la méthode HTTP, jamais par l'URL. Donc /activities et non /getActivities.
Le pluriel
Pour la cohérence des URI : customers plutôt que customer_list.
Des URL courtes
Le nommage sensé favorise la compréhension de l'API.
Des minuscules
Avec un tiret - ou un tiret bas _ comme séparateur.

Les middlewares

Ce sont des fonctions qui ont accès à trois choses : l'objet de requête req, l'objet de réponse res, et la fonction middleware suivante next.

Elles s'exécutent avant les routes, sur le chemin de la requête. express.json() en est un : il lit le JSON du body et le rend disponible dans req.body.

Le fichier de données simulées

// db/mock-activities.js
let activities = [
    {
        id: 1,
        name: "Cours de natation",
        startDate: "2026-09-01",
        duration: 60,
    },
];

// export default : une seule chose exportee
export default activities;

Les deux méthodes de tableau à ne pas confondre

MéthodeRetourneSert à
find()L'objet lui-même, ou undefinedLire une activité (GET)
findIndex()La position, à partir de 0, ou -1Remplacer (PUT) ou supprimer (DELETE)

On a besoin de la position pour écrire dans une case (activities[index] = ...) ou pour retirer un élément (splice(index, 1)).

Le calcul de l'id, question classique

activities.length + 1 est faux : si on supprime une activité au milieu, la longueur diminue et le prochain ajout recrée un id déjà utilisé.

const id = Math.max(...activities.map(a => a.id)) + 1;
La limite de cette approche : le tableau vit dans la mémoire du programme. Un redémarrage du serveur efface toutes les modifications et remet les données de départ. C'est précisément pour ça qu'on branche ensuite une vraie base de données.

Objectif

Tester une API REST

Le prof cite deux outils, connais les deux. Ils envoient des requêtes HTTP comme le ferait un site web, une application mobile ou un programme.

Postman

Une application qui permet de créer des requêtes HTTP à l'aide d'une interface graphique.

La méthode
Le menu déroulant à gauche de l'adresse : GET, POST, PUT, DELETE.
L'URL
http://localhost:3000/api/activities, avec ou sans id selon la route.
Le Body
Uniquement pour POST et PUT. Onglet Body, bouton raw, puis le menu de droite sur JSON.
Send
La réponse s'affiche en bas, avec son code de statut et son temps d'exécution.

curl

Un programme en ligne de commande, dans le terminal, qui envoie des requêtes HTTP vers un serveur. Même rôle que Postman, sans interface graphique.

curl -X POST http://localhost:3000/api/activities
  -H "Content-Type: application/json"
  -d '{"name":"test", "duration":"2"}'

Les options à reconnaître : -X donne la méthode, -H ajoute un en-tête, -d porte les données du body.

Les codes de statut HTTP

Le prof en note quatre en particulier, marqués ci-dessous.

CodeFamilleSignification
200 OK2xx, succèsLa requête a réussi
201 Created2xx, succèsUne ressource a été créée, réponse idéale d'un POST
403 Forbidden4xx, erreur du clientLe client n'a pas les droits d'accès, le serveur refuse de répondre
404 Not Found4xx, erreur du clientLe serveur n'a pas trouvé la ressource demandée
500 Internal Server Error5xx, erreur du serveurLe serveur a rencontré une situation qu'il ne sait pas traiter

Retiens la logique des familles : 2xx tout va bien, 4xx la faute du client, 5xx la faute du serveur.

Format des données : une API REST échange du JSON. Ce n'est pas tout à fait du JavaScript : en JSON, les noms de propriétés sont entre guillemets doubles et il n'y a pas de virgule après le dernier élément.

Objectif

Backend, frontend, serveur web, API REST

L'architecture, telle que le prof la dessine

1 · clientNavigateur ou PostmanEnvoie une requête HTTP
2 · serveurServeur web HTTPReçoit la demande et la transmet
3 · backendApplication Express, l'APITrouve la route et exécute le code
4 · donnéesLa base de donnéesInterrogée par une requête SQL, renvoie des résultats
5 · retourRéponse HTTPUn code de statut et des données en JSON

Dans notre projet, l'étape 4 était remplacée par le fichier JavaScript de données simulées, jusqu'à ce qu'on branche MySQL.

Serveur web
L'ordinateur qui reçoit et répond aux demandes des utilisateurs voulant utiliser une application, mobile ou web. Il fonctionne sur le modèle client / serveur : le navigateur demande le contenu via HTTP, le serveur le trouve et le renvoie via HTTP. S'il ne peut pas le fournir, il renvoie un code d'erreur comme 404 ou 403.
Frontend
Ce que voit et utilise l'utilisateur : la partie visible, l'interface graphique. Langages : HTML, CSS, JavaScript, avec des outils comme Vue.js ou React.
Backend
Ce qui se passe derrière : la partie cachée qui traite les données, interagit avec la base de données et gère la logique métier. Langages : JavaScript avec Node.js, PHP, Python, Java, C#.
Client
Celui qui envoie la requête : un navigateur, une application mobile, ou un autre programme. Le client demande, le serveur répond, jamais l'inverse.
API REST
Application Programming Interface — Representational State Transfer. Un ensemble de routes sur un serveur, qui permet à des clients de lire et manipuler des données via le protocole HTTP.
Ressource
La chose manipulée par l'API : des utilisateurs, des produits, des articles, des activités. Chaque ressource est accessible par une URL, et on utilise les méthodes HTTP pour agir dessus.
Pourquoi séparer frontend et backend ? Parce que plusieurs clients différents — un site, une application mobile, un autre programme — peuvent utiliser la même API. La logique et les données sont écrites une seule fois, et restent sur le serveur, donc protégées.

Réponds avant de cliquer

Quelle est la différence entre un langage compilé et un langage interprété ?
Un langage compilé est traduit en une fois en langage machine et produit un fichier exécutable ; il est rapide mais doit être compilé avant. Un langage interprété est traduit ligne par ligne au moment de l'exécution, ne produit aucun exécutable, et s'exécute directement, mais plus lentement.
JavaScript est-il compilé ou interprété ? Quel est son interpréteur côté serveur ?
Interprété. Son interpréteur côté serveur est Node.js, comme python l'est pour Python.
Cite deux langages compilés et deux langages interprétés.
Compilés : C, C++, Rust, Go, Swift. Interprétés : Python, JavaScript, PHP, Ruby, Bash.
Que veut dire l'acronyme API REST, en entier ?
Application Programming Interface — Representational State Transfer. C'est un ensemble de routes sur un serveur qui permet à des clients de lire et manipuler des données via HTTP.
Qu'est-ce qu'un serveur web ?
Un ordinateur qui reçoit et répond aux demandes des utilisateurs voulant utiliser une application. Il fonctionne sur le modèle client / serveur, via le protocole HTTP.
Quelle est la différence entre frontend et backend ?
Le frontend est ce que voit et utilise l'utilisateur, l'interface graphique : HTML, CSS, JavaScript. Le backend est la partie cachée qui traite les données, interagit avec la base et gère la logique métier : Node.js, PHP, Python, Java, C#.
Par quelles trois choses une route est-elle définie ?
Sa méthode HTTP, son path qui est l'URL, et la fonction à exécuter. Cette fonction a deux paramètres : la requête et la réponse.
Qu'est-ce qu'un middleware ?
Une fonction qui a accès à l'objet de requête req, à l'objet de réponse res, et à la fonction middleware suivante next. Elle s'exécute avant les routes. express.json() en est un.
Différence entre npm install express --save et --save-dev ?
--save déclare une dépendance nécessaire pour faire tourner l'application en production. --save-dev déclare une dépendance utile uniquement en développement, comme nodemon.
Quelles sont les règles de nommage d'une URL REST ?
Des noms et jamais des verbes, au pluriel, en minuscules, avec un tiret ou un tiret bas comme séparateur, et aussi courtes que possible. L'action est portée par la méthode HTTP.
Que signifient 200, 403, 404 et 500 ?
200 : la requête a réussi. 403 : le client n'a pas les droits d'accès, le serveur refuse de répondre. 404 : le serveur n'a pas trouvé la ressource. 500 : le serveur a rencontré une situation qu'il ne sait pas traiter.
Cite les deux outils pour tester une API REST.
Postman, avec une interface graphique, et curl, en ligne de commande dans le terminal.
À quoi sert app.use(express.json()) ?
C'est un middleware qui permet à Express de lire le JSON envoyé dans le body des requêtes. Sans lui, req.body n'est pas exploitable et un POST échoue.
Différence entre req.params et req.body ?
req.params contient les paramètres de l'URL, déclarés avec deux points comme /:id. req.body contient les données envoyées dans le corps de la requête, pour un POST ou un PUT.
Pourquoi écrit-on parseInt(req.params.id) ?
Parce qu'un paramètre d'URL est toujours du texte. Sans conversion, la comparaison "2" === 2 serait fausse et aucune activité ne serait trouvée.
Différence entre find() et findIndex() ?
find() retourne l'objet trouvé. findIndex() retourne sa position dans le tableau, en commençant à 0. On a besoin de la position pour remplacer ou supprimer un élément.
Que se passe-t-il au redémarrage du serveur, avec des données simulées ?
Toutes les modifications sont perdues. Le tableau vit dans la mémoire du programme et repart de son état initial, tel qu'écrit dans le fichier JavaScript.
Pourquoi ne met-on jamais node_modules sur GitHub ?
Parce que ce sont des milliers de fichiers téléchargés, que npm install recrée à l'identique à partir du package.json.

Corrections fréquentes

Les pièges

« Node.js est un langage »
Non. Le langage est JavaScript. Node est l'interpréteur qui l'exécute hors du navigateur.
« JavaScript est compilé »
Non, il est interprété : traduit ligne par ligne à l'exécution, sans fichier exécutable généré.
« Express est un langage » ou « une base de données »
Non. Express est un framework pour Node, qui simplifie l'écriture d'un serveur web.
Confondre l'URL et le verbe
Une URL nomme une ressource, un nom. C'est le verbe HTTP qui porte l'action. Donc /api/activities/2 avec DELETE, jamais /api/deleteActivity/2.
Nommer une ressource au singulier
Le prof recommande le pluriel : customers plutôt que customer_list.
Mettre un id dans l'URL d'un POST
Le POST se fait sur /api/activities sans id : c'est le serveur qui attribue l'identifiant.
Calculer l'id avec length + 1
Faux dès qu'une suppression a eu lieu. Il faut le plus grand id existant, plus 1.
Confondre 403 et 404
403, la ressource existe mais l'accès est refusé. 404, la ressource est introuvable.
Écrire du JSON avec des guillemets simples
Le JSON exige des guillemets doubles autour des noms de propriétés, et interdit la virgule après le dernier élément.
« Le serveur peut envoyer une requête au client »
Dans ce modèle, non. Le client demande, le serveur répond. C'est toujours le client qui déclenche l'échange.
