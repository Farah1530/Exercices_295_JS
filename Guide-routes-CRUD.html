Routes CRUD des activités

Les quatre opérations de l'API, chacune avec les étapes du code et la marche à suivre dans Postman. Serveur Express 5, données en mémoire dans un tableau, port 3000.

Le circuit d'une requête

Postmanenvoie la méthode, l'URL et parfois un body
app.jslit le JSON puis oriente vers le routeur
activities.jstrouve la route qui correspond
le tableaulecture, ajout, remplacement ou suppression
res.json()renvoie la réponse et termine

Où voyagent les données

MéthodeRôleId dans l'URLBody
GETLireSeulement pour une activité préciseAucun
POSTCréerNon, le serveur choisit l'idObligatoire
PUTModifierOuiObligatoire
DELETESupprimerOuiAucun

Une règle simple pour s'en souvenir. L'URL sert à désigner quelle activité. Le body sert à transporter son contenu. Une activité entière ne tiendrait pas proprement dans une adresse, d'où le body.

Créer

POST

Ajouter une activité

/api/activities

Le client envoie une activité sans id. Le serveur lui en attribue un, l'ajoute au tableau, et renvoie l'activité complète pour que le client découvre son id.

Étapes du code
  1. Lire le body. La déstructuration sort les trois champs de req.body en une ligne.
  2. Calculer l'id. On prend le plus grand id existant et on ajoute 1.
  3. Construire l'objet en assemblant l'id et les trois champs reçus.
  4. Ajouter au tableau avec push(), qui place l'élément à la fin.
  5. Répondre avec un message et l'activité créée.
Le code
activitiesRouter.post('/', (req, res) => {
    // 1. les données envoyées par le client
    const { name, startDate, duration } = req.body;

    // 2. le prochain id libre
    const id = Math.max(...activities.map(activity => activity.id)) + 1;

    // 3. et 4. on construit puis on ajoute
    const newActivity = { id, name, startDate, duration };
    activities.push(newActivity);

    // 5. on répond
    const message = `L'activité ${newActivity.name} a bien été créée !`;
    res.json({ message: message, activity: newActivity });
});
Pourquoi pas activities.length + 1 ? Parce que supprimer une activité au milieu fait retomber la longueur, et le prochain ajout recréerait un id déjà utilisé. Deux activités porteraient le même numéro. C'est exactement le point que la consigne demande de traiter.
Test dans Postman
  1. Méthode POST, URL http://localhost:3000/api/activities, sans id à la fin.
  2. Onglet Body, bouton raw, puis le menu de droite sur JSON à la place de Text.
  3. Coller l'activité, sur une seule ligne pour éviter les accolades ajoutées automatiquement :
    {"name": "Cours de guitare", "startDate": "2026-10-01", "duration": 75}
  4. Send. 200 OK et la réponse contient le nouvel id.
  5. Vérifier avec un GET sur la liste complète, la nouvelle activité est à la fin.

Modifier

PUT

Mettre à jour une activité

/api/activities/:id

Un mélange des deux autres routes. L'id de l'activité visée vient de l'URL, comme pour le DELETE. Les nouvelles valeurs viennent du body, comme pour le POST.

Étapes du code
  1. Lire l'id dans l'URL et le convertir en nombre, car req.params.id est du texte.
  2. Lire les nouvelles valeurs dans le body.
  3. Trouver la position avec findIndex(), car on doit écrire dans la case du tableau.
  4. Remplacer l'ancienne activité, en gardant le même id.
  5. Répondre avec l'activité telle qu'elle est maintenant.
Le code
activitiesRouter.put('/:id', (req, res) => {
    // 1. et 2. l'id vient de l'URL, le contenu vient du body
    const id = parseInt(req.params.id);
    const { name, startDate, duration } = req.body;

    // 3. la position dans le tableau
    const index = activities.findIndex(activity => activity.id === id);

    // 4. on remplace, en réutilisant le même id
    activities[index] = { id, name, startDate, duration };

    // 5. on répond
    const message = `L'activité ${activities[index].name} a bien été modifiée !`;
    res.json({ message: message, activity: activities[index] });
});
Garder le même id. Si l'id venait du body, le client pourrait changer l'identité de l'activité en la modifiant. On reprend donc toujours celui de l'URL.
Test dans Postman
  1. Méthode PUT, URL http://localhost:3000/api/activities/2, avec l'id cette fois.
  2. Body en raw et JSON, comme pour le POST.
  3. Envoyer l'activité complète, pas seulement le champ modifié :
    {"name": "Atelier peinture modifie", "startDate": "2026-09-05", "duration": 100}
  4. Send. 200 OK et la réponse montre l'activité 2 avec ses nouvelles valeurs.

Supprimer

DELETE

Supprimer une activité

/api/activities/:id

La route la plus courte. Rien à envoyer, tout tient dans l'URL. Le serveur retire l'élément du tableau et confirme.

Étapes du code
  1. Lire l'id dans l'URL et le convertir en nombre.
  2. Trouver la position de l'activité avec findIndex().
  3. Supprimer avec splice(index, 1), qui retire un élément à cette position.
  4. Répondre par un message de confirmation.
Le code
activitiesRouter.delete('/:id', (req, res) => {
    // 1. l'id vient de l'URL
    const id = parseInt(req.params.id);

    // 2. sa position dans le tableau
    const index = activities.findIndex(activity => activity.id === id);

    // 3. supprimer 1 élément à partir de cette position
    activities.splice(index, 1);

    // 4. on répond
    res.json({ message: 'Activité supprimée' });
});
Test dans Postman
  1. Méthode DELETE, URL http://localhost:3000/api/activities/2.
  2. Body sur none, il n'y a rien à envoyer.
  3. Send. 200 OK et le message de suppression.
  4. Vérifier avec un GET, il reste une activité de moins.

Les deux méthodes à ne pas confondre

MéthodeRetourneExemple pour l'id 2Utilisée dans
find() L'objet lui-même { id: 2, name: "Atelier peinture", ... } GET par id
findIndex() La position, à partir de 0 1 PUT et DELETE

Le PUT et le DELETE ont besoin de la position, parce qu'écrire dans une case ou en retirer une demande de savoir où elle se trouve. Le GET veut juste le contenu.

Erreurs rencontrées et leur cause

500, avec Cannot destructure property 'name' of 'req.body'
Le Body est vide. En Express 5, une requête sans body donne req.body non défini, et la déstructuration plante. Coller le JSON dans la zone Body.
Une page HTML disant Cannot POST /...
Express n'a pas trouvé la route. L'URL a une faute, ou il manque /api au début.
Une activité créée avec des champs vides
Le menu du Body est resté sur Text au lieu de JSON. Le serveur reçoit du texte brut et ne trouve aucun champ.
Les modifications disparaissent toutes seules
Comportement normal. Le tableau vit en mémoire, donc chaque redémarrage de nodemon, déclenché par une sauvegarde de fichier, remet les données de départ.
Un id qui n'existe pas donne un résultat étrange
findIndex() retourne alors -1. Le DELETE supprime le dernier élément et le PUT écrit hors du tableau. La gestion d'erreur n'est pas demandée dans l'exercice, mais c'est la question piège classique.
